# Developer guide

How this profile README works, and how to change it without breaking anything.

## TL;DR

- **Text, colours, roles, section titles, social handles** live in `scripts/build_assets.py`.
  Edit the `CONTENT` block, run `python scripts/build_assets.py`, commit, push.
- **Project cards, tech icons, links, page order** live in `README.md`. Edit and push.
- **Instagram / LinkedIn numbers** are the `REACH` list in `scripts/build_assets.py`.
  Edit and push; that's all.
- **Stats card, reach strip and snake** are generated by a GitHub Action every
  12 hours and on every push. Never edit them by hand; they aren't even on `main`.
- **Never hand-edit files in `assets/`.** They are overwritten the next time the script runs.
- **Run `git pull` before you start editing.** A workflow commits to `main` up to twice a
  day (the daily quote), so your local copy falls behind. Without the pull, `git push` is
  rejected.

## How it fits together

```mermaid
flowchart LR
  subgraph main branch
    BA[scripts/build_assets.py] -- you run it locally --> AS[assets/*.svg]
    RM[README.md]
  end
  subgraph GitHub Action — every 12h + on every push
    WF[profile-assets.yml] --> BS[scripts/build_stats.py]
    WF --> SNK[Platane/snk]
  end
  BS --> OUT[(output branch<br/>stats.svg · counters.svg)]
  SNK --> OUT2[(output branch<br/>snake-dark.svg · snake-light.svg)]
  AS --> RM
  OUT --> RM
  OUT2 --> RM
  EXT[shields.io · skillicons.dev · holopin · komarev] --> RM
```

**Why custom SVGs?** GitHub strips all CSS, `<style>` and JavaScript from README HTML, so a
README can't animate anything itself. An SVG *image* can: its own CSS/SMIL animations
still run when GitHub shows it. Every animated piece is therefore an SVG with its styling
baked in. The catch: an SVG shown as an image can't load fonts or pictures from the web,
can't run JS, and is clickable only as a whole. That's why each social link is its own image.

**Why self-hosted?** The popular shared services (`github-readme-stats.vercel.app`, the
activity-graph service) were shut down and showed broken images. Everything important here
is generated into this repo, so it can't disappear.

## File map

| Path | What it is | Edit it? |
|---|---|---|
| `README.md` | The page itself: layout, project cards, links, tech icons | ✅ directly |
| `scripts/build_assets.py` | All static SVG art + the `CONTENT` block (text, roles, colours) | ✅ then rebuild |
| `scripts/build_stats.py` | Live stats card + reach strip (runs in the Action) | only to change the card's design |
| `.github/workflows/profile-assets.yml` | Schedule + steps that build and publish the live images | only to change schedule/colours |
| `assets/hero.svg` | Glitching name, rotating roles, synthwave floor | ❌ generated |
| `assets/terminal.svg` | The `neofetch` terminal | ❌ generated |
| `assets/headers/*.svg` | The six numbered section headers | ❌ generated |
| `assets/social/*.svg` | LinkedIn / Instagram / GitHub buttons | ❌ generated |
| `assets/divider.svg`, `assets/footer.svg` | Divider under the hero, wave footer | ❌ generated |
| `scripts/daily_update.py` | Quote list + the script that swaps the daily quote line | ✅ add/remove quotes |
| `.github/workflows/daily-readme.yml` | Schedule for the daily quote commits | only to change frequency |
| `output` branch | `stats.svg`, `counters.svg`, `snake-*.svg` | ❌ force-replaced every run |

The scripts use only the Python standard library (3.8+). No `pip install` needed.

## Common edits

Every edit to `scripts/build_assets.py` ends the same way:

```bash
python scripts/build_assets.py
git add -A
git commit -m "Update profile"
git push
```

### Change your roles, name, greeting or the hero labels

In `scripts/build_assets.py`, edit `NAME`, `GREETING`, `STATUS` (top-left, e.g. "OPEN TO
COLLABS"), `AFFILIATION` (top-right) or `ROLES` (the lines that type themselves out). Any
number of roles works; the timing adjusts automatically. Keep each role under ~35 characters
so it stays comfortably inside the banner.

### Update the neofetch terminal

Edit `NEOFETCH`, a list of `("Label", "value")` pairs. Values must stay under ~55
characters; the script **stops with an error** naming the line if one is too long. Label
colours cycle through blue, red, yellow, green automatically.
`OPEN_TO_DIR` / `OPEN_TO` control the `ls` command at the bottom.

### Rename a section, or add one

Edit `SECTIONS`: `(file name, TITLE, subtitle)` in page order. The number chip and the
progress bar ("SECTION 03/06") are computed from the list, so adding a seventh section
updates every header. For a new section, also add its image to `README.md`:

```html
<img src="./assets/headers/<file name>.svg" width="100%" alt="07 · Title — subtitle" />
```

### Change a social handle or link

- The **text on the button** is `SOCIALS` in `scripts/build_assets.py`.
- The **link it opens** is the `<a href="…">` around it in `README.md`, near the top.

Adding a new platform (say X or a portfolio) needs a new `SOCIALS` entry **and** an `ICONS`
entry: a tile colour and a glyph drawn on a 24×24 grid (a [Simple Icons](https://simpleicons.org)
path fits as-is; give it `fill="#fff"`). Then add another `<a><img src="./assets/social/<name>.svg" height="54"></a>` to
the README.

### Update your Instagram / LinkedIn numbers

LinkedIn and Instagram don't offer a public way to read these counts, so they're typed by
hand in `REACH` in `scripts/build_assets.py`:

```python
REACH = [  # (platform, number, label)
    ("linkedin", "500+", "connections"),
    ("linkedin", "765", "followers"),
    ("instagram", "969", "followers"),
]
```

Change a number, commit and push. The workflow redraws the reach strip on every push, so
you **don't** need to run `build_assets.py` for this. The number is plain text, so `1.2K`
or `500+` work as written. Remove a row to hide it; add one (e.g. `("instagram", "120",
"posts")`) to show more. Rows for the same platform share one icon, in list order. A
platform needs an `ICONS` entry (see above) to get its icon.

GitHub followers and profile views are added automatically after these.

### Add a project or hackathon card

In `README.md`, the cards are an HTML table in rows of two. Copy a whole `<td>…</td>` block,
change the title/text, and keep two `<td>` per `<tr>`. For an odd number of cards, the last
row can have one `<td>`.

The small tags are [shields.io](https://shields.io) static badges:
`https://img.shields.io/badge/<LABEL>-<MESSAGE>-<HEXCOLOR>?style=flat-square&labelColor=161B22`.
In the label/message, `_` is a space, `__` is a real underscore and `--` is a real dash.
Palette: `4285F4` blue, `EA4335` red, `FBBC05` yellow, `34A853` green.

### Add or remove tech icons

Edit the `?i=` list in the matching `skillicons.dev` URL in `README.md`, e.g.
`?i=react,flutter,tailwind`. All valid names are listed at <https://skillicons.dev>.

### Change the colours

The palette constants sit at the top of `scripts/build_assets.py` (`BLUE`, `RED`,
`YELLOW`, `GREEN`, `BG`, …). Both scripts import them, so after changing them, rebuild
assets locally **and** push (the Action rebuilds the stats card with the new colours).
The snake's colours are in `.github/workflows/profile-assets.yml` (`color_snake`,
`color_dots`).

### Change the footer

`FOOTER_TITLE` and `FOOTER_LINE` in `scripts/build_assets.py`.

## The live images (stats, reach strip, snake)

`.github/workflows/profile-assets.yml` runs:

- **every 12 hours** (00:00 and 12:00 UTC, i.e. 5:30 AM/PM IST),
- **on every push** to `main`,
- **manually**: GitHub → **Actions** → **Profile assets** → **Run workflow**.

It builds `stats.svg` and `counters.svg` with `scripts/build_stats.py`, builds the snakes
with [Platane/snk](https://github.com/Platane/snk), and force-pushes all four to the
`output` branch. The README loads them from
`https://raw.githubusercontent.com/Apurba2509/Apurba2509/output/<file>`.
If any step fails, nothing is pushed and the previous images stay up.

What the numbers mean:

| On the card | Source |
|---|---|
| Contributions, streaks, commits, weekly chart | Your contribution calendar, **past year** |
| Pull requests | All time |
| Stars earned, top languages | Your own public, non-fork repos (up to 100), languages by bytes of code |
| LinkedIn connections/followers, Instagram followers | **Typed by hand** in `REACH` (see below) |
| GitHub followers | GitHub, at the last run |
| Profile views | [komarev](https://komarev.com), read at the last run |

Profile views are counted by the invisible 1×1 komarev image in the README (every visit
counts) and **displayed** on the chip, which refreshes every 12 hours. Each Action run
reads the counter once, so it adds about 2 views a day (plus one per push).

### Preview the stats card locally

```bash
python scripts/build_stats.py --sample --out preview/stats.svg
```

This writes `preview/stats.svg` and `preview/counters.svg` with **made-up numbers**,
labelled "sample data", so you can check a design change. Open the files in a browser.
`preview/` is git-ignored. For real numbers locally, drop `--sample` and set
`GITHUB_TOKEN` to a [personal access token](https://github.com/settings/tokens) (no scopes needed):

```bash
GITHUB_TOKEN=<your token> python scripts/build_stats.py --out preview/stats.svg
```

## Daily quote commits

`.github/workflows/daily-readme.yml` swaps the quote line near the bottom of the README
(between `<!-- DAILY:START -->` and `<!-- DAILY:END -->`) and commits it **as you**, using
your GitHub no-reply address. Those commits count on your contribution graph.

- It runs twice a day, at **09:07** and **19:43 IST**. Each run updates with a **60%**
  chance, so about 48% of days get one commit, 36% get two, and 16% get none. GitHub
  sometimes starts scheduled runs late or skips one when it's busy.
- The commit message is `docs: refresh daily quote`.
- **Add or remove quotes:** edit `QUOTES` in `scripts/daily_update.py`. It never picks the
  quote that's already showing.
- **Change how often:** edit the `cron` lines (times are UTC; IST = UTC + 5:30) and/or the
  `0.6` in the workflow. `1` means every run commits.
- **Force one now:** Actions → **Daily README refresh** → **Run workflow**. Manual runs
  always commit.
- **Pause it:** Actions → **Daily README refresh** → `···` → **Disable workflow**.
  **Remove it:** delete the workflow file and the `DAILY` block in the README.
- **Don't delete the `DAILY` markers** while the workflow is on. The run fails with
  "markers not found" and nothing is committed.
- Commits pushed by a workflow don't trigger other workflows. The stats/snake refresh still
  runs on its own 12-hour schedule.

## Previewing changes before you push

- **Any SVG in `assets/`**: drag it into Chrome. The animations play.
- **The whole README**: open `README.md` in VS Code / Antigravity and press
  `Ctrl+Shift+V`. Local images render; the live images load from GitHub.
- The preview's CSS isn't identical to github.com, so do a final check on your profile
  after pushing.

## Troubleshooting

**An image is broken right after I pushed.**
When a new file is created, GitHub's raw-file CDN may still serve a cached "404" for up
to ~5 minutes. Wait, then hard-refresh (`Ctrl+F5`). Avoid opening a raw URL before the
file exists; that's what gets the 404 cached.

**The stats card / snake / reach strip never appear.**
Open **Actions** and click the latest **Profile assets** run.
- Red ✗ on "Publish to the output branch" with a 403 → **Settings → Actions → General →
  Workflow permissions** → "Read and write permissions" → save → re-run.
- Red ✗ on "Build stats card" → read the log. A GitHub API hiccup is retried 3 times; if
  it still fails, just re-run the workflow later.
- Scheduled runs stopped → GitHub can pause scheduled workflows in repos with no activity
  for 60 days. Re-enable it on the Actions tab, or just push any change.

**"Current streak: 0 days".**
You have no contributions today or yesterday. It counts up from your next commit/PR.

**A number looks lower than on my profile.**
The card uses the past-year window and public repos. Contributions only count if they're
on a repo's default branch and made with an email linked to your account.

**My hand edit to an SVG disappeared.**
`build_assets.py` regenerates every file in `assets/`. Make the change in the script.

**`python` isn't found / opens the Microsoft Store.**
Use `py scripts/build_assets.py` on Windows, or `python3` on macOS/Linux.

**`git push` says "rejected … fetch first".**
The daily-quote workflow committed since you last pulled. Run `git pull --rebase`, then
`git push` again.

**Git warns "LF will be replaced by CRLF".**
Harmless on Windows.

## Rules of thumb

- Keep the README's HTML simple: GitHub allows `<div align>`, `<p align>`, `<img>`, `<a>`,
  `<table>`, `<picture>` and a few more, and strips `style` attributes, `<style>` and scripts.
- Give every image an `alt` text. It's what screen readers and search engines see.
- Don't commit to the `output` branch; the next run wipes it.
- If you change the repo name or your username, update the `Apurba2509` URLs in
  `README.md` (the Action picks up the username automatically).
